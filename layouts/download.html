The warning you will see, and why

{{- if or (not site.Params.signing.macos) (not site.Params.signing.windows) }}

Being straight about this rather than letting you find out: the current builds are not yet code-signed, so both operating systems will warn you about them. That warning is about a missing signature, not about anything found in the file — neither system has inspected the code.

{{- end }} {{- if not site.Params.signing.macos }}

macOS

Recent macOS refuses an unsigned application on the first attempt, with a message about not being able to verify it is free of malware and only a Done button. To run it anyway: open System Settings → Privacy & Security, scroll to the Security section, and use Open Anyway beside the blocked application. It is asked once.

This goes away with Apple Developer notarization, which is registered and being worked through. Until then, the honest position is that you are trusting a build you can inspect the source of rather than a signature.

{{- end }} {{- if not site.Params.signing.windows }}

Windows

SmartScreen shows Windows protected your PC for executables it has not seen often enough to have formed an opinion about. Choose More info, then Run anyway. Every new release resets this, because the reputation is attached to the exact file.

{{- end }}

Verifying what you downloaded

Each release lists a SHA-256 for every file. Comparing it against the file you have proves you got the bytes the build published, and that nothing altered them on the way.

macOS or Linux

shasum -a 256 ~/Downloads/SideScopes-macos.zip

Windows, in PowerShell

Get-FileHash -Algorithm SHA256 $HOME\Downloads\SideScopes-windows.zip

The value it prints should match the one beside that file on the releases page. If it does not, do not run it — and please say so.

Building it yourself

The surest check is not to take a binary at all. The repository builds with CMake and a C++20 compiler on all three platforms, and CONTRIBUTING.md has the toolchain setup and the checks that run on every commit.
