# sidescopes.org

The SideScopes website. [Hugo](https://gohugo.io/), no theme, no
JavaScript framework, and no third-party request on any page except the
analytics beacon — which is itself behind four gates.

## Develop

```console
$ hugo server
```

Screenshots are served from R2 in production and from a local mount under
`hugo server`, so a page can be reviewed the moment the pipeline writes a
shot and before anything is uploaded. See **Screenshots** below.

## Build

```console
$ hugo --gc --minify
```

The site lands in `public/`.

## How it is put together

- **`content/learn/`** — the guides. Written here, for photographers who
  may never have used a scope. This is the part of the site that has to
  stand on its own whether or not anyone downloads anything.
- **`content/docs/`** — **generated**, do not edit. `scripts/sync-docs.sh`
  copies the reference documentation out of the application repository at
  the tag `docsRef` in `hugo.toml` pins, so the site documents the release a
  visitor can actually download rather than the development branch. CI runs
  `scripts/sync-docs.sh --check` and fails if the two have drifted.
- **`content/news/`** — releases and articles. `/news/index.xml` is the
  feed; RSS is switched on for this section alone.
- **`data/media/`** — one small manifest per screenshot, written by the
  workbench pipeline. Committed. The images themselves are not.
- **`data/release.json`** — the current version, refreshed daily by
  `.github/workflows/release-data.yml` from the GitHub Releases API, so no
  version number on the site is ever hand-typed.

## Screenshots

Every scope picture is a capture of the running application, so that what a
visitor sees here is what they will see after downloading. None of them are
drawings, and none of them live in this repository.

They are generated by `scripts/site-shots.py` in the private workbench,
which pins the scope stack, the window size and the interface scale, shows a
public-domain reference photograph, drives a region over it, captures the
window by id, and crops away the toolbar and the status row — leaving the
panes, which teach, and dropping the chrome, which dates.

```console
$ scripts/site-shots.py --list           # in the workbench
$ scripts/site-shots.py                  # regenerate everything
$ scripts/media-upload.sh                # publish to R2
```

Two ways to place one:

```
{{< figure name="vectorscope-cast" >}}
```

in content written here, and plain markdown in documentation shared with the
application repository:

```markdown
![A vectorscope with a cool cast](https://media.sidescopes.org/shots/vectorscope-cast.png)
```

The second form renders in GitHub's markdown preview as an ordinary image,
and `layouts/_markup/render-image.html` upgrades it here into a responsive
`<picture>` with AVIF and WebP at several widths — one line of markdown,
correct in both places, no second source to maintain.

## Deploying

Cloudflare Pages builds two branches and no others. `release` is the
published site and `staging` is a preview; both are pushed deliberately from
green `main`. Everything outside `release` is served `noindex`. The project,
its domains and the media bucket are managed in the private
`sidescopes-infra` repository.
